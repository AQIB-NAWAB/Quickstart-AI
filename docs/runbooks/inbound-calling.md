# Runbook: Inbound Calling Operations & Troubleshooting

This runbook covers operational procedures, configuration paths, health verification, and incident mitigation for the QuickStart AI voice telephony platform.

---

## 1. Supported Telephony Topology Paths

QuickStart AI supports three production topologies for answering inbound phone calls:

| Topology | Carrier / Number Source | Inbound Ingress Edge | Best For | Required Credentials |
|---|---|---|---|---|
| **Path A: Platform Telnyx Numbers** | Platform Telnyx Account | LiveKit Cloud SIP | Default SaaS experience; users purchase numbers directly in the app. | `TELNYX_API_KEY`, `TELNYX_PUBLIC_KEY`, `LIVEKIT_*` |
| **Path B: BYO SIP via LiveKit Cloud** | Customer PBX / Carrier | LiveKit Cloud SIP | Cloud-hosted SIP ingress with customer's existing DIDs / carriers. | `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `LIVEKIT_SIP_ENDPOINT` |
| **Path C: BYO SIP via Self-Hosted SIP** | Customer PBX / Carrier | Self-Hosted `livekit/sip` + `livekit-server` | Full data-plane sovereignty; on-prem PBXs, private networks, zero cloud telephony billing. | None (self-hosted LiveKit stack credentials generated via `render-config.sh`) |

## 3. Go-Live Checklist

- [ ] **DNS & SIP Reachability**:
  Run `node scripts/check-sip-stack.mjs <host>` to confirm SIP OPTIONS returns `200 OK` or `404 Not Found`.
- [ ] **Webhook Ingress**:
  Ensure `${VOICE_PUBLIC_BASE_URL}/voice/telephony/livekit/webhook` is publicly accessible and reachable from the LiveKit server.
- [ ] **Speech Pipeline Configured**:
  Verify `DEEPGRAM_API_KEY` and TTS provider keys (`CARTESIA_API_KEY` or `ELEVENLABS_API_KEY`) are active.
- [ ] **Inbound Readiness Verified**:
  Open the Staff UI (**Voice** &rarr; **Numbers**). Confirm the readiness panel status is green with no blocking error checks.
- [ ] **Agent Assigned**:
  Every active number must have an assigned agent. Calls to unassigned numbers are rejected immediately with `SIP 480`.

## 5. Incident Playbooks

### Incident 1: Inbound calls failing with SIP 403 Forbidden
* **Symptom:** Carrier reports `403 Forbidden` on SIP INVITE.
* **Diagnosis:**
  1. The carrier's source IP address is not included in the number's allowlist.
  2. Or SIP Digest Authentication username/password does not match.
* **Mitigation:**
  - In Staff UI &rarr; **Voice** &rarr; **Numbers**, locate the number.
  - Click **IPs** and add the carrier's signalling IP subnets.
  - If using credentials, click **Rotate** and update the PBX with the new password.

---

### Incident 2: Inbound calls failing with SIP 480 Temporarily Unavailable
* **Symptom:** Caller hears busy/rejection tone immediately.
* **Diagnosis:**
  1. The dialed number exists in the database but has no `assigned_agent_id`.
  2. Or workspace inbound cap (`VOICE_WORKSPACE_INBOUND_CAP`, default 100) is exceeded.
* **Mitigation:**
  - Assign an active agent to the number in the web UI.
  - Check active calls in the Live Inbound dashboard. If valid traffic, increase `VOICE_WORKSPACE_INBOUND_CAP`.

---

### Incident 3: One-Way Audio (Caller cannot hear agent)
* **Symptom:** Call connects, but caller hears dead silence.
* **Diagnosis:**
  1. RTP UDP ports (`10000-20000`) blocked by cloud security group.
  2. Self-hosted `sip.yaml` missing `use_external_ip: true`, causing SDP to advertise private IP (`10.x.x.x` or `172.x.x.x`).
* **Mitigation:**
  - Verify firewall permits inbound UDP `10000-20000`.
  - Re-run `deploy/sip/render-config.sh` and restart the SIP stack: `make sip-up`.

---

### Incident 4: Leaked or Compromised SIP Credentials
* **Symptom:** Suspicious calls arriving from unauthorized endpoints.
* **Mitigation:**
  1. Navigate to **Voice** &rarr; **Numbers**.
  2. Click **Rotate** on the affected number.
  3. A new 192-bit cryptographic password is generated immediately.
  4. Ensure a strict source IP CIDR allowlist is also enforced on the trunk.
